# TMOG (Task Manager OG) (research notes)

> Coreography research notes. Sources accessed 2026-10-17.

## Summary

- TMOG is Dave Plummer's (original Windows Task Manager author, 1996) cross-platform reimagining: free system monitor for macOS, Windows, Linux, with a paid "Pro" tier. Current version is 1.0.0 RTM (Windows has a 1.0.1 hotfix); it went macOS-beta July 31, 2026, added Windows/Linux August 23, and was at RTM by early October 2026 (privacy notice updated Oct 6 already describes RTM; the site publishes no release date).
- It was substantially "vibe-coded": Plummer wrote a ~107-page spec, fed it to Claude Code, and had a working app in roughly 3.5-4.5 hours, then iterated. This origin is a major theme in its reception, both positive (shipping speed) and negative (HN derision, "vibecoded slop").
- Architecture: one shared C++20 measuring core with three fully native shells: Swift + AppKit on macOS (macOS 14+, universal Apple Silicon + Intel, signed and notarized, direct download only: a free Mac App Store beta was the original plan, but Apple's sandboxing forbids the process listing and process termination the app needs), C++/Win32 + Direct2D/DirectComposition on Windows 11, C++/Qt 6 on Linux. No Electron, no web view.
- Twelve named destinations: Summary, Performance, Processes, System Info, Startup apps, Users, Services, Power & Freq, Connections, Installed Apps, Disk Space, Benchmarks. The last five are Pro. The sidebar shows a PRO divider (confirmed in the Windows walkthrough); the Mac sidebar parity-gap observation (Connections and App History absent from a Mac screenshot) is from screenshots (unverified).
- The measurement philosophy is the most interesting part for Coreography: "Measured, never invented." Zero means a measured zero, unavailable is labelled unavailable (literally rendered as "Unavailable" in the UI), missing samples leave visible gaps instead of interpolated lines, PIDs are paired with creation identity, and the app can monitor itself.
- Pro costs $39.95 USD one-time for 3 seats (any mix of platforms), $99.99 for 9 seats, sold via Lemon Squeezy. Headline Pro feature is Flight Recorder: record, save, scrub and replay seven telemetry panels in a cross-platform `.tmogtrace` format. Other Pro adds: Power & Freq, Connections, Installed Apps, Disk Space, Benchmarks; iPhone remote view is Mac-only Pro.
- Reception is polarized. Praise: native feel, responsiveness, depth (P/E core views, GPU engines, thermal sensors), honest "unavailable" states, cross-platform parity, the author responds rapidly to feedback. Criticism: the look is widely panned ("ugly", "fake antivirus interface", neon/glow, cyberpunk), it uses more resources than Windows Task Manager, memory readings differ from Task Manager's, sensor coverage is spotty, and it is closed source with a paid tier.
- The visual design is the key anti-reference for Coreography: segmented VFD "phosphor" meters with bloom/glow, a wide sci-fi display font for page titles, per-subsystem rainbow neon accents on near-black, a glowing wordmark inside the sidebar, and dense grids of tiny graphs. Ideas worth taking are real; the skin is what to avoid.

## Tools

### TMOG (Task Manager OG)

- **Status**: Active. Publisher: Plummers' Software LLC. Version 1.0.0 RTM (current since at least Oct 6, 2026; site publishes no date); Windows-only hotfix RTM.1 (1.0.1) fixes post-sleep self-closing, watchdog, and sensor-driver crash issues. Free edition; TMOG Pro $39.95 (3 seats) or $99.99 (9 seats), one-time, Lemon Squeezy. macOS 14+, universal dmg; Windows 11 x64/ARM64 (installer or zip); Linux x86_64/aarch64 (AppImage, .deb, .tar.gz; needs glibc 2.35+, Qt 6.4+ for non-AppImage). Closed source; feedback via public GitHub tracker `PlummersSoftwareLLC/tmog-feedback` (113 open issues as of 2026-10-17; the site's feedback page links `davepl/tmog-feedback`, which redirects there).
- **What it shows**: The twelve destinations, per the site:
  - Summary: dashboard tiles. Four vertical VFD column meters (CPU %, Clock, Temp, GPU %); a CPU Overview graph combining utilization (green area), temperature (orange line) and kernel usage (red area); "Top CPU processes" table (PID, Name, CPU, GPU, Memory; rows that change flash green then fade); Memory Utilization graph; bottom cards for Disks, Network, Energy (watts), GPU, NPU, Thermals, each with a mini segmented meter strip.
  - Performance: left rail lists metrics with sparklines (CPU, Memory, GPU 0, NPU 0, Disks, Network, Energy, Thermals). CPU detail: segment strip meter, a grid of one filled-area mini graph per logical processor (24 shown on an M2 Ultra), P-core/E-core color coding, overall/logical-processor/NUMA view switch, and a stat block (Utilization, Speed, Processes, Threads, Up time in d:h:m:s, Base speed, Physical cores, Virtualization, L1/L2/L3 cache, Frequency governor/driver, Sockets, Logical processors, Virtual machine, Power preference). Unmeasurable fields render literally as "Unavailable". Memory: utilization graph plus In use, Available, Committed, Cached, Swap used/available/total, Speed, Slots used, Form factor, Type, Compressed, Wired, App memory, Pressure, Pressure load %, Page ins/outs. Disks: per-device or combined activity/throughput/capacity. Network: adaptive-scale throughput graph, Receive/Send rates, totals, interface name, connection type, hardware address, IPv4/IPv6, "Connection details..." button. Energy: watts meter, power history, Thermal state / Power mode / Power source chips, and a "Processes with the highest estimated energy demand" bar list (own relative score; footnote admits macOS does not publish Activity Monitor's Energy Impact calculation). Thermals: CPU/SoC hotspot graph, thermal pressure, hotspot temp, per-die sensor cards (Die 0-3) each with temp and sparkline.
  - Processes: live process hierarchy grouped under collapsible "Applications (n)" headers; toolbar with "Process View" dropdown and a "Filter by name, user, or PID" field; columns Name, PID, Status, User name, CPU usage (inline bar), Memory usage; a bottom inspector pane for the selection showing full path, Identity (Parent, User, Status, Architecture), Lifetime (Started, Uptime, Threads, Priority), Processor (CPU, CPU time, GPU, NPU), Memory (Footprint, Private, Page faults), Disk (Reading, Writing).
  - System Info: static machine information (the data class of Windows' msinfo32), pulled into the app.
  - Startup apps: enable/disable toggles, sortable.
  - Users: per-logged-in-user resource usage.
  - Services: running/available services list, sortable by running state.
  - Power & Freq (Pro): HWiNFO-style wall of power and frequency readings across the machine; core and SoC power on supported systems.
  - Connections (Pro): listening/exposed ports and per-app connections.
  - Installed Apps (Pro): installed apps with versions and estimated sizes.
  - Disk Space (Pro): largest-files view using a circular, pseudo-3D radial layout rather than a rectangular treemap.
  - Benchmarks (Pro): CPU, GPU, disk and internet-speed tests producing a score comparable against other users.
  - Extras observed: an App History view on Windows (needs elevated restart), an F12 full-screen "system-load screensaver" with shared rendering on all platforms, a status bar ("Native providers healthy · N processes · Generation N" plus tiny LED-style indicators and an HDD activity light option) (unverified), a "Replace Windows Task Manager" setting (unverified; "Replacing Windows Task Manager" appears as a viewer request in Shop Talk #93), a self-monitoring toggle, and an always-on-top "popout" mini-meter window (see skins below).
- **How it shows it**: Dark near-black chrome; left icon sidebar with pill selection; a "PRO" divider mid-list; glowing neon "TMOG" wordmark at sidebar bottom; Settings and Colors buttons pinned below it. Page titles use a wide, squared geometric display font; labels are small gray caps; numbers are large and bright. Signature widget: segmented "VFD" meters, rows or columns of small rounded squares where lit segments glow (bloom effect) over very dark unlit segments. Graphs are thin-grid scrolling area/line charts with a glow halo, a white chevron at the right edge marking "now", "Scrolling history" captions, and a compressed timeline (seconds near the present, coarser intervals going back). Per-subsystem accent colors: CPU green, kernel red, temperature orange, memory magenta, network and GPU blue, energy yellow, thermals orange, NPU red. Themes: Light and Dark ("Full color · Saturation 7"), Green/Amber/Blue phosphor (single-hue CRT looks), Mono (dark, Saturation 0); bloom toggle and selectable visual frame rates (animates up to 60 Hz).
- **Ideas worth taking**: Explicit availability states rendered in the UI ("Unavailable", "Power access restricted", "Degraded" with reason strings like "Logical volume capacity fallback" (unverified example)); gaps instead of interpolated lines; zero-vs-unmeasured distinction; PID + creation-identity pairing so recycle-safe actions; self-monitoring mode; compressed/nonlinear time axis on scrolling graphs; P-core vs E-core color coding and per-logical-processor grids; process rows that flash on change then fade; per-metric summary dashboard answering "why is my computer slow"; process inspector pane with grouped Identity/Lifetime/Processor/Memory/Disk facts; honest footnote where a number is an estimate (energy demand); minimal network surface (only an update check); offline-verified signed license entitlement.
- **Weaknesses / avoid**: The whole visual skin: bloom/glow on everything, neon palette per subsystem, sci-fi display type for titles, glowing in-app wordmark, dense boxed mini-graph grids, skeuomorphic VFD meters as the default presentation. Resource cost: measured ~120 MB memory and 3-4% CPU by PC Gamer (vs Task Manager ~105 MB, <1%); a monitor that heavy is self-defeating. Reading mismatches vs platform tools (Chrome 11 GB vs Task Manager's 8 GB) confuse users even when defensible; metric semantics need documenting. Sensor coverage is spotty (thermals stuck at 16.9 C in one review, "Unavailable" USB disk activity bugs in tracker). Closed source + paywalled destinations generated distrust. Landing page copy reads as LLM-generated marketing ("More signal. Less hunting.") and was mocked on HN.

### Flight Recorder (.tmogtrace)

- **Status**: Pro-only feature, shipping on all three platforms at 1.0.0. Records, saves, scrubs and replays telemetry in one interchangeable `.tmogtrace` file format.
- **What it shows**: The same seven telemetry panels as live view (CPU, GPU, memory and others per store copy), replayable after the fact; a demo video shows real CPU spikes in live view.
- **How it shows it**: Record/scrub/replay interaction model; marketing pitch is "record a slowdown, scrub back after the spike is gone" (postmortem for transient jank).
- **Ideas worth taking**: Session capture + scrubbable replay is the single most distinctive feature vs Activity Monitor; a shared, documented trace format enables cross-session and cross-machine comparison. This is a strong candidate for a future Coreography Pro-like feature or a free differentiator.
- **Weaknesses / avoid**: Paywalling the feature that reviewers called the most interesting draws complaints; no export/open tooling is documented (unverified whether traces can be exported to CSV/JSON; users explicitly requested "exportable performance data").
- **Sources**: https://store.tmog.org/ , https://tmog.org/ , https://podtail.nl/podcast/dave-s-garage-shop-talk/tmog-dave-answers-your-questions-rates-23-feature-/

### Popout window and skin system

- **Status**: Shipping. The popout is a small always-on-top desktop readout; skins are user-installable data files, documented publicly.
- **What it shows**: Eight channels: `cpu`, `memory`, `gpu`, `thermal` (the TEMP quadrant), `disk`, `network`, `power` (wattage in the bottom strip) and `alert` (the thermometer in the bottom row); per-skin layout varies (meters, round dials, history graphs, labelled rows). Tiled quadrant styles accept only `cpu`/`memory`/`gpu`/`thermal`; the `rows` style also carries `disk` and `network`.
- **How it shows it**: A skin is JSON (`format`, `id`, `name`, `author`, `description`, optional SF Symbol). Single `.tmogskin` file or a `.tmogskin/` folder package containing `skin.json` plus images (PNG/JPEG/HEIC/TIFF/GIF/PDF; file names only, no paths or URLs, nothing executable). Tokens cover window/tile surfaces (solid or vertical gradient), ink colors, per-channel accents (`cpu`, `memory`, `gpu`, `thermal`, `disk`, `network`, `power`, `alert`), meter `style` (`bars` default, `gauge`, `graph`, `vertical` column meters, `rows`), lit/unlit segment colors, optional green-to-red positional ramp, segment counts 4-48, `flat` mode (no bloom), dial bezel/needle options, fonts (size 5-24 pt, weights, designs incl. monospaced/rounded/serif), title-bar and badge geometry. Skins live in `~/Library/Application Support/TMOG/Skins/` (or inside the app bundle for built-ins); picked via popout chevron menu, Settings > Interface, or View > Popout Skin; missing skins fall back to Default. Built-in: Default, Winamp, Windows Media Player, Console, Traces, Windows Task Manager (grey chrome, navy title bar, green column meters on black). Aurora Fleet/Gauge/Dash are site-only examples.
- **Ideas worth taking**: "A skin is data, not code": sandboxed declarative JSON with no executable capability is a safe extensibility model. Named reverse-DNS ids, graceful fallback to a default skin, and shipping editable examples inside the bundle are all worth copying if Coreography ever offers a compact/popout mode.
- **Weaknesses / avoid**: The built-in examples are nostalgia skins (Winamp, WMP); on macOS this reads as skinning-for-its-own-sake and works against a native look. A popout plus skins is scope creep unless it serves a real "ambient monitor" use case.
- **Sources**: https://tmog.org/rtm/skins.html

### TMOG Pro, licensing and extras

- **Status**: Selling since Beta 3 (Sep 7, 2026 per X post); active at RTM. Lemon Squeezy is merchant of record.
- **What it shows**: Pro unlocks Flight Recorder, Power & Freq, Connections, Installed Apps, Disk Space, Benchmarks; iPhone remote view of the Mac Summary page (Mac-only); Apple-Silicon-only Pro features flagged in store copy.
- **How it shows it**: License key + purchase email activate in-app; one HTTPS POST sends key, email, salted SHA-256 of IOPlatformUUID/MachineGuid, and computer name; the app stores an unencrypted signed `license.json` in Application Support; all later verification is offline, no periodic check-in; deactivation releases the seat. iPhone pairing shows six characters on both screens to compare (no typed password), streams readings directly over LAN, read-only, announces as "Task Manager TMOG" on the network only during 3-minute pairing. Update checks are HTTPS GETs with no version or metrics (macOS uses an ephemeral session); the only web-controlled surface is whether to show a Pro link. An opt-in "AI Advisor" prototype in development builds sends a diagnostic snapshot to a configured local-network inference server, excluding usernames/paths/serials.
- **Ideas worth taking**: Per-seat offline entitlement with a signed local file and no server dependency after activation is a user-respecting licensing design. The privacy posture is unusually thorough: masked origin logs, no crash upload, Plausible (not GA) analytics, GPC/DNT honored, measurement off outside the US. The iPhone remote-view design (LAN-only, read-only, compare-codes pairing) is a clean pattern if Coreography ever adds companion viewing.
- **Weaknesses / avoid**: Early activation bugs (Pro keys not unlocking, "license was refused" on Mac, seats consumed by reinstalls) generated support churn; the free/Pro split puts roughly a third of destinations behind a paywall, which reviews flagged. Fine-print disclaimers ("not a commitment to ongoing development") are honest but unconfidence-inspiring.
- **Sources**: https://store.tmog.org/ , https://tmog.org/rtm/pro-info.html , https://tmog.org/rtm/privacy.html , https://tmog.org/rtm/support.html , https://github.com/PlummersSoftwareLLC/tmog-feedback/discussions/358

### Platform-specific engineering notes

- **Status**: Shipping; documented per-platform.
- **What it shows**: Linux CPU power comes from `powercap` (`/sys/class/powercap/*/energy_uj`, root-readable since kernel 5.10); TMOG refuses to run as root or ship a workaround and instead shows "Power access restricted" and documents an optional udev group-read rule. Windows AMD Ryzen temperature/power requires the free AMD Ryzen Master Monitoring SDK plus running TMOG as administrator; the UI names the missing step ("need a free add-on from AMD", "Restart TMOG as administrator") with links. Firmware temperatures are labelled "ACPI thermal zone" to distinguish board sensors from CPU package temp.
- **How it shows it**: Every sensor absence carries a named reason and, where possible, an actionable link; degraded fallbacks say "Degraded" plus the fallback mechanism used (unverified).
- **Ideas worth taking**: This is the best concrete implementation of "measured, never invented": label the sensor source (ACPI zone vs package temp), name the missing privilege or driver, link the remedy, never silently substitute. For Coreography on macOS this maps to: label SMC/powermetrics-derived values, name entitlement requirements, distinguish estimated vs measured watts.
- **Weaknesses / avoid**: The long tail of sensor/driver variance is a permanent support burden; 113 open tracker issues include USB disk activity unavailable, temps not shown, wrong PCIe link speed, a 5-second periodic hiccup, and stutters on an M5 Mac when unfocused.
- **Sources**: https://tmog.org/rtm/linux.html , https://tmog.org/amd-thermals.html , https://github.com/PlummersSoftwareLLC/tmog-feedback/issues

- **Weaknesses / avoid**: Shipping with the neon look as default made the visual design the story instead of the engineering; reviewers spent more words on bloom than on the measurement model. Overhead of a 60 Hz animated monitor undermines the product's premise.

## Cross-cutting patterns

- **Honesty as a feature**: explicit availability states, named fallback sources, gaps over interpolation, self-monitoring, and in-UI remediation links. This is TMOG's real design contribution and is independent of its skin.
- **Graph-first, list-second**: Summary and Performance lead; the process table is one destination among twelve. Matches Coreography's premise exactly.
- **One metric, one accent**: every subsystem owns a neon color used consistently across sidebar, meter, graph and stat text. Consistent, but the palette itself is the problem (saturated neon on black).
- **Segmented meters everywhere**: VFD-style lit-segment bars serve as both gauges and ambient decoration; strong skeuomorphism.
- **Nonlinear history**: compressed timeline (dense seconds near now, coarse history behind) on every scrolling graph; solves the "1-minute vs 1-hour" problem in one widget.
- **Extensibility as data**: declarative JSON skins, documented token schema, safe by construction.
- **Ambient surfaces**: popout widget, menu/status-bar indicators, F12 screensaver, iPhone remote view. The monitor wants to live everywhere, not just in its window.
- **Cross-platform truth claim**: same metrics and semantics across OSes via a shared core; but parity gaps (Connections, App History, sensor coverage) and platform caveats are where bugs concentrate.
- **Freemium gate in navigation**: Pro destinations are visible-but-locked items in the sidebar, which makes the upsell constant but also makes the free product feel amputated.

## Implications for Coreography

1. Steal the measurement contract wholesale: every metric carries an availability state (measured / unavailable / degraded / restricted), rendered inline; gaps in history are drawn as gaps; label the source of each reading ("SMC sensor", "powermetrics estimate", "unavailable: needs helper"). This is the single most copy-worthy thing about TMOG.
2. Answer "why is my computer slow" in one glance: a Summary-style dashboard correlating CPU, energy, thermals, disk and network with top offenders is validated by reviewers; but render it in native macOS visual language (SF Symbols, system fonts, semantic colors, real vibrancy), not neon bloom.
3. Keep one accent per subsystem but use muted, HIG-consistent hues (e.g. systemBlue/Green/Orange/Purple at reduced saturation, luminance-adaptive for light/dark). TMOG's green=m CPU/magenta=memory mapping is fine; the saturation-7 neon execution is not.
4. Compressed-timeline scrolling graphs are worth copying: seconds of resolution near "now", coarser resolution for older samples, with a clear "now" edge marker.
5. Adopt PID+start-time identity pairing for all process actions; it is cheap and prevents kill-the-wrong-process bugs.
6. Consider Flight Recorder-style capture early: a compact ring buffer + saveable trace is harder to retrofit than to design in. Even without a Pro tier, "scrub the last hour" is a headline differentiator vs Activity Monitor.
7. Budget your own footprint visibly: TMOG burns 3-4% CPU to look pretty and reviewers noticed. Coreography should idle under ~1% with adaptive frame rates, pause rendering when occluded/unfocused, and ship a self-monitoring readout as proof.
8. Do not mimic the chrome: no bloom/glow, no segmented VFD skeuomorphism as default, no custom display font, no glowing logo in the sidebar, no phosphor themes. If retro skins ever ship, make them opt-in extras, never the default face; the default should look like Apple shipped it.
9. Process table details worth copying: rows flash briefly on appearance/change then fade; grouped applications section; filter field covering name/user/PID; inline usage bars in cells; a bottom inspector pane with grouped Identity/Lifetime/Processor/Memory/Disk facts; Ctrl-held freeze of the live list refresh so a moving row can be clicked safely (TMOG lacks it, Thurrott noticed).
10. Privacy posture is table stakes for this category: no telemetry, update check only, local-only licensing verification. TMOG's privacy page is a good template; also note they run ads measurement on the *site*, which drew no complaints but is unnecessary for a free tool.
11. Learn from their support surface: name the required privilege/driver in the UI and link the fix; never leave a dead gauge. Also document metric semantics (their Chrome 11 GB vs Task Manager 8 GB discrepancy cost them credibility even though defensible).
12. Distribution lesson: sandboxed App Store is impossible for this feature set (process listing/killing, sensors), so plan on direct dmg + Sparkle-style updates, signed and notarized, like TMOG.
